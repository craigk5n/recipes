# Internationalization (i18n) System

This document describes the modern PHP 8.1+ internationalization system for the Recipes application.

## Overview

The i18n system uses:
- **JSON files** for translations (easy to edit, version control friendly)
- **Type-safe PHP code** with enums and readonly classes
- **ICU MessageFormat** for complex messages and pluralization
- **Fallback chain** for missing translations

## Quick Start

### Basic Usage

```php
use function Recipes\I18n\t;
use function Recipes\I18n\et;

// Simple translation
echo t('navigation.home'); // "Home"

// With parameters
echo t('phrases.serves', ['count' => 4]); // "Serves 4"

// Echo directly
et('recipe.title'); // Echoes "Title"
```

## Adding Translations

### 1. Create a Translation File

Create a new JSON file in `/translations/` named with the locale code:

```
translations/
├── en.json    (English - default)
├── es.json    (Spanish)
├── fr.json    (French)
└── de.json    (German)
```

### 2. Add Locale to Enum

Edit `/src/I18n/Translator.php` and add the new locale to the `Locale` enum:

```php
enum Locale: string
{
    case ENGLISH = 'en';
    case SPANISH = 'es';
    case FRENCH = 'fr';
    case GERMAN = 'de';
    case ITALIAN = 'it';
    // Add your new locale:
    case PORTUGUESE = 'pt';
}
```

### 3. Copy and Translate

Copy `en.json` to your new locale file and translate all values:

```json
{
  "app": {
    "name": "Recetas k5n",
    "title": "Gestor de Recetas"
  },
  "navigation": {
    "home": "Inicio",
    "add_recipe": "Añadir Receta"
  }
}
```

## Translation Keys

Keys use dot notation for nesting:

```json
{
  "section": {
    "subsection": {
      "key": "value"
    }
  }
}
```

Access with: `t('section.subsection.key')`

## Parameters and Pluralization

### Simple Parameters

```json
{
  "phrases": {
    "welcome": "Welcome, {name}!"
  }
}
```

```php
echo t('phrases.welcome', ['name' => 'John']);
// Output: Welcome, John!
```

### Pluralization (ICU Format)

For pluralization support, use ICU MessageFormat:

```json
{
  "phrases": {
    "ingredient_count": "{count, plural, one {# ingredient} other {# ingredients}}"
  }
}
```

```php
echo t('phrases.ingredient_count', ['count' => 1]);  // "1 ingredient"
echo t('phrases.ingredient_count', ['count' => 5]);  // "5 ingredients"
```

## Auto-Detection

The system automatically detects the user's preferred language from their browser:

```php
use Recipes\I18n\Locale;

// From Accept-Language header
$locale = Locale::fromBrowser('es-ES,es;q=0.9,en;q=0.8');
// Returns: Locale::SPANISH
```

## Fallback Chain

If a translation is missing, the system falls back:

1. Current locale (e.g., `zh_CN`)
2. Base language (e.g., `zh`)
3. Default locale (always `en`)

## Advanced Usage

### Direct Translator Access

For more control, use the Translator class directly:

```php
use Recipes\I18n\Translator;
use Recipes\I18n\Locale;

$translator = new Translator('/path/to/translations', Locale::FRENCH);

// Change locale dynamically
$translator->setLocale(Locale::SPANISH);

// Check if translation exists
if ($translator->has('custom.key')) {
    echo $translator->trans('custom.key');
}
```

### Message Parameters Class

For type safety, use the MessageParameters class:

```php
use Recipes\I18n\MessageParameters;

$params = new MessageParameters([
    'recipe_name' => 'Pasta',
    'servings' => 4,
    'prep_time' => 30
]);

echo t('recipe.summary', $params);
```

## Best Practices

1. **Use descriptive keys**: `recipe.ingredients` not `ri`
2. **Organize by feature**: Group related translations under a section
3. **Keep English updated**: English is the fallback, keep it complete
4. **Use parameters**: Don't concatenate strings, use parameters
5. **Test pluralization**: Always test with count=0, 1, and 2+

## Adding New Translations to Existing Locales

1. Add the key to `en.json` first
2. Copy the key to all other locale files
3. Translate the values in each locale file
4. Run tests: `php vendor/bin/phpunit tests/TranslatorTest.php`

## Troubleshooting

### Translation not found
- Check the JSON file is valid: `php -r "json_decode(file_get_contents('translations/en.json')); echo json_last_error_msg();"`
- Verify the key path matches exactly (case-sensitive)
- Check that the locale is in the Locale enum

### Locale not detected
- Ensure the locale is added to the Locale enum
- Check browser's Accept-Language header
- Verify the translation file exists

### Special characters not displaying
- Ensure JSON files are saved as UTF-8
- Check your HTML has `<meta charset="UTF-8">`
